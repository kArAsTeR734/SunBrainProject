# Создание домашнего задания

## Цель

Пользователь создаёт домашнее задание на странице «Домашние задания»: задаёт название, формат экзамена, тему, количество
задач и дедлайн. Созданная работа появляется в его списке и календаре и доступна для выполнения.

## Сценарий

1. На странице домашних заданий отображается кнопка «Создать домашнее задание». Если список пуст, кнопка находится над
   Empty State. Кнопка доступна и при непустом списке, чтобы можно было создать следующую работу.
2. По нажатию открывается форма создания. Пользователь указывает название, формат экзамена (ЕГЭ или ОГЭ), предмет, одну
   тему выбранного предмета и формата, общее количество задач и дедлайн.
3. Тема загружется для выбранного предмета и формата. Во время загрузки показывается индикатор; при ошибке — сообщение и
   возможность повторить запрос; при отсутствии тем — понятное пустое состояние. При смене предмета или формата
   несовместимый выбор тем сбрасывается.
4. Пользователь отправляет форму. Пока запрос выполняется, повторная отправка недоступна. При успехе форма закрывается,
   список домашних заданий обновляется и содержит созданную работу. При ошибке показывается понятное сообщение,
   введённые значения сохраняются для повторной попытки.
5. Форму можно закрыть без создания задания. Закрытие формы происходит при клике вне поля действия формы или при нажатии
   на кнопку Esc. Форма открывается как модальное окно.

## Поля и проверка

- Название обязательно, после удаления пробелов не пустое; ограничение длины согласовать с текущим полем базы (до 255
  символов).
- Формат экзамена и предмет обязательны; предлагаются только поддерживаемые сочетания.
- Необходимо выбрать одну тему, относящуюся к выбранным формату и предмету.
- Количество задач — обязательное положительное целое число. Допустимый максимум 30 задач, минимум 5 задач.
- Дедлайн обязателен и должен быть в будущем. Формат ввода в виде ДД.ММ.ГГ и время например 15.11.26 17:00. Дедлайн
  может задаваться в виде 2 отдельных полей дата и точное время.
- Ошибки полей показываются рядом с ними; введённые данные не теряются. Backend повторно проверяет данные и
  принадлежность выбранных тем.
- Если подходящих задач недостаточно, работа не создаётся; пользователь видит причину и может изменить параметры.
  Частичное создание не допускается.

## Состояния и доступность

- Создание доступно авторизованному пользователю для собственной работы; работа не появляется в списках других
  пользователей.
- Кнопка и форма доступны с клавиатуры; элементы имеют понятные подписи, ошибки связаны с полями. Если используется
  модальное окно, фокус переводится в него и возвращается к кнопке после закрытия.
- При загрузке списка и при ошибке его получения сохраняются существующие состояния страницы; расположение кнопки
  остаётся в том же месте, где она должна быть согласно текущему состоянию.
- Создание записи, привязка задач и назначение пользователю выполняются как единая операция: при ошибке не остаётся
  неполной работы.
- Задачи брать из существующего банка, если по выбранной теме задач нет, сообщить об этом пользователю в виде ошибки 
  создания домашнего задания по указанной причине.
- Выбор предмета ограничен одним предметом на работу

## Текущее состояние проекта

- Страница ученика показывает список через `HomeworkList`; при пустом списке выводится `DataFallback`.
- Существующие маршруты домашних заданий предоставляют список, просмотр и проверку ответа, но отдельного маршрута
  создания пользователем нет.
- Текущая модель `homeworks` хранит один `subject_id` и один `topic_id`, а подробный просмотр ожидает одну тему.
- Существует отдельная AI-генерация работы по одному номеру задания, но она не реализует описанную форму и произвольный
  выбор нескольких тем.
- В каталоге часть тем пока не содержит задач; сценарий недостаточного количества обязателен для проверки.

## Критерии приёмки

1. Кнопка видна над Empty State и доступна при наличии работ; она открывает форму.
2. В форме доступны все перечисленные поля, включая выбор темы; тема соответствует выбранным предмету и формату.
3. Загрузка, ошибка и отсутствие темы отображаются пользователю; после смены предмета или формата старые несовместимые
   темы не остаются выбранными и сбрасываются.
4. Невалидные данные и нехватка задач не приводят к созданию работы; пользователь получает объяснение.
5. При успешном создании появляется одна работа с указанным названием и дедлайном и согласованным количеством подходящих
   задач; её можно открыть и выполнять.
6. При ошибке запроса данные формы сохраняются, повторная отправка возможна, дубликаты из-за повторного нажатия во время
   запроса не создаются.
7. Новая работа доступна только создавшему её пользователю; существующие работы продолжают отображаться и открываться.
8. Основной сценарий и состояния ошибки проверены на frontend и backend, в том числе при выборе нескольких тем.
