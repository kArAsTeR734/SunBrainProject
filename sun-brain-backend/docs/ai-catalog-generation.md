# Генерация каталога

Конфигурация: `SIMPLE_CLAW_BASE_URL=https://simple-claw.ru/v1` и `SIMPLE_CLAW_API_KEY`
в локальном `.env` или переменных контейнера. `.env.production` автоматически не загружается
в dev-compose. Файлы окружения исключены из Git и Docker build context.
Миграция: `npm run migrate:deploy`. Docker-образы включают Python 3 для проверки SVG и арифметики.

Все маршруты требуют `Authorization: Bearer <access token>` платформы. Пока роли
не ограничивают эти маршруты — это временное поведение по спецификации.

## Контракт

- `POST /api/ai/catalog/runs` с `{"budgetRubles":50,"reviewBeforePublish":false}`:
  создаёт новую партию по easy/medium/hard для каждой записи `topics` предмета `emath`.
- `GET /api/ai/catalog/runs/:runId`: прогресс, кандидаты, проверки, опубликованные ID и журнал вызовов.
- `POST /api/ai/catalog/runs/:runId/advance`: выполняет **одну попытку одной позиции**.
  Повторять этот запрос, пока есть pending/failed с attempts < 3 и есть бюджет.
  Проверка провайдера выполняется один раз на запуск. SDK не повторяет запросы автоматически.
  409 означает, что другой запрос генерации/публикации ещё выполняется.
- `POST /api/ai/catalog/runs/:runId/publish` с `{"itemIds":[1,2]}`: публикует проверенные
  кандидаты. Для первой партии использовать `reviewBeforePublish:true`, просмотреть задачи
  и рисунки, затем вызвать publish. Повторная публикация тех же позиций не создаёт задач.
- `POST /api/ai/catalog/runs/:runId/reject` с `{"itemId":1,"reason":"Причина"}`:
  отклоняет ещё не опубликованного кандидата для повторной генерации.

Ответы используют стандартный envelope `{success,data}` / `{success:false,message}`.
Статусы запуска: pending, awaiting_review, completed, partial, budget_exhausted, provider_error.
Ошибки отдельных позиций находятся в `items[].error`. Три попытки **всего** на позицию,
продолжение не сбрасывает счётчик или бюджет. После исчерпания попыток позиция остаётся failed.
Новое создание запуска явно создаёт новую партию, а не продолжает старую.

## Проверки и ограничения

Используется Responses API, `gpt-6.1-terra`. SimpleClaw не вернул подтверждение reasoning,
поэтому по решению пользователя параметр размышлений не передаётся. Перед генерацией
пробный ответ должен сообщить ту же модель. Это свидетельство ответа шлюза,
а не независимая аттестация внутренней маршрутизации поставщика.

Отдельный запрос без истории заново решает задачу и проверяет тему, условие, подробное
решение, ответ, рисунок и похожие условия. Его арифметическое выражение вычисляет Python
с точными рациональными числами через ограниченное AST; код модели не исполняется.
Проверка вычислений не доказывает правильность того, как выражение выведено из условия.
Семантическая проверка той же моделью может разделять ошибки генератора, особенно в геометрии.
Абсолютная гарантия математической корректности этим методом не обеспечивается.

Для SVG проверяются XML, namespace, viewBox, разрешённые элементы/атрибуты, отсутствие
скриптов, внешних ресурсов и выходящих за viewBox текстовых координат. Смысл и читаемость
проверяются моделью; первая партия дополнительно просматривается агентом в браузере.
Хотя бы easy получает рисунок в темах планиметрии, стереометрии, векторов,
графиков, производных и функций. Решение может содержать отдельный `solutionImageSvg`.

Нормализованный хеш условия сравнивается со всеми существующими задачами перед публикацией
под блокировкой. Генератор видит до 12 последних условий своей темы и успешные условия
одноимённой темы текущей партии. Проверяющий получает восемь наиболее похожих условий
из всего каталога и успешных кандидатов партии по пересечению слов. Это сокращает расход
токенов; смысловые дубли вне выборки или с полностью иной лексикой могут не обнаружиться.

Ответы — точные конечные десятичные числа. Для тем с доказательствами/несколькими ответами
создаётся числовая подзадача, а не полный аналог соответствующего задания экзамена.
Внутренние номера тем не трактуются как актуальные номера позиций ФИПИ.
Источник экзаменационного формата: https://fipi.ru/ege/demoversii-specifikacii-kodifikatory

## Учёт бюджета

Перед каждым платным вызовом резервируется консервативная оценка: UTF-8 байты сообщений
плюс запас на обрамление, максимальный выход, максимальные ставки input/cache-write и
output/reasoning из текущего `/models`, плюс 10% запаса. Запросы не содержат изображений,
инструментов или серверной истории: SVG передаётся как текст.
Известный usage уменьшает резерв до оценки по фактическим токенам с теми же запасами.
При сетевой ошибке, отсутствии usage или падении процесса полный резерв остаётся потраченным.
`charged_rubles` — консервативный учтённый расход, не подтверждённое списание с баланса.
При изменении тарифной модели провайдера, дополнительных сборах или несоблюдении лимитов
поставщиком расчёт требует пересмотра. Недельный лимит API-ключа у провайдера дополнительно
может ограничить списания, но приложение не изменяет настройки ключа.

Успешно проверенные задания публикуются атомарно вместе с отметкой позиции.
Резерв сохраняется до обращения к провайдеру, поэтому после перезапуска нет скрытого
обнуления расходов. Публикация сериализована также между разными партиями.

## Проверки разработки

- `node --test tests/catalog-validation.test.js`
- `CATALOG_INTEGRATION_TEST=1 node --test tests/catalog-generation.integration.test.js`
  с DB-переменными: создаёт отдельную временную schema, проверяет продолжение,
  конкурентные запросы, идемпотентную публикацию, лимиты и неоднозначные ошибки.
- Frontend: `npm run lint`, `npm run build`.
