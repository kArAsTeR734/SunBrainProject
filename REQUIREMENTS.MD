# Требования к разработке SunBrain

## Архитектура и формы

- Соблюдайте FSD: пользовательские действия и их формы размещайте в `features`, переиспользуемые данные сущностей — в `entities`, композицию блоков страницы — в `widgets`. Импортируйте слайсы через публичный API и избегайте зависимостей между соседними слайсами одного слоя.

- HTTP-запросы размещайте в `api`, а хуки мутаций с управлением состоянием запроса и обновлением кеша — в `model/mutations`.
- Для валидации всех новых и изменяемых форм используйте Zod.
- Разделяйте модальные окна и формы на отдельные компоненты. Общие элементы интерфейса размещайте в `shared/ui`, когда они используются повторно.
- Следуйте принципам DRY и KISS: избегайте дублирования, лишних состояний и избыточных абстракций; распределяйте ответственность между компонентами.
- Если в shared/ui есть своя реализация нативного компонента, например Input или Button, то следует использовать реализацию из shared/ui.

## Redux во frontend

- В React-коде отправляйте Redux-действия через `useAppDispatch`, а состояние читайте через `useAppSelector`. Импортируйте оба хука из `@shared/lib`.
- Прямые импорты `useDispatch` и `useSelector` из `react-redux` допускаются только в модуле, который предоставляет `useAppDispatch` и `useAppSelector`. Селекторы конкретной сущности держите в её модели.
